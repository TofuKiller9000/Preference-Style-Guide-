DOCUMENTATION / STYLE GUIDE

Preference Style Guide

This guide provides a consistent documentation & reference for how to correctly format and type the preferences for Doctor's Accounts at ROE Dental Laboratory.

Clear Communication

Referencing this guide when adding, creating, or removing preference will help not only you, but everyone at ROE Dental Lab. We're counting on you to know that here at ROE, our preference ie excellent service.

Purpose

It is your duty to utilize this guide when interacting with the preference system to maintaing a uniform look and readability. If this is not followed, preferences can easily become overloaded and unreadable, leading to confusion and annoyance. Preferences are one of the many ways we can show the quality of our work and care to our accounts here at ROE Dental Lab.

Goals

  • Improve consistency and readability
  • Reduce duplicated and contradictory instructions
  • Make important information easier to locate

System Basics

What are preferences?

Preferences are a set of rules and guidelines expressed by a doctor for how we can best serve them, and the products we make. Each doctor's account has their own unique set of preferences that are printed on a work ticket whenever a new case is generated.

  • Even if an account has multiple doctors, only one preference page will be generated
  • Preferences are shared across an account for all cases

How are preferences applied?

Each department can be assigned a specific set of preferences. For example, if Dr. Smith wants all denture cases to include a name, you can include that preference in the Denture Department Preference tab. When a denture case is scheduled, this preference will be printed.

There are some departments whose preferences will always be include such as:

  • Data Entry
  • Team QC Quality Control
  • General Preferences

To avoid repeating information, the preference system limit the departments that can be given preferences.

Formatting Rules

Limitations

It is important to limit what can and cannot be included to keep an overall uniformity to all preferences. The goal is to make is that all preferences look like they were written by the same person. This increases not only the readability, but also the speed at which a technician can find important information.

Additionally, the text input of the system is limited in what it can showcase. It cannot utilize things that are helping you read this very document such as colored text, varying spaces, bold/italic/underlined text, headers, lists, and bullet points. As such, it is important to follow these guidelines that have been crafted specifically to work within these limitations.

Headers & Breaks

Breaks

Each preference section should be sandwiched by two 38-character lines of the '=' key, and two '|' key. These breaks denote the beginning and end of a department's specific preferences. This helps guide the eye from section to section with differences in the length of text. Think of them as the red-light-green-light-go indicators of our eyes.

FORMATTING EXAMPLE 

|======================================|
[Department Text]
|======================================|
Rule

There should be no space ('Enter' key) before or after the breaks.

General Headers

Headers are all-caps of text that are the beginning of a subsection of preferences for a department. All preference sections should have a minimum of one-header that is the general header that denotres the default standards of that department.

FORMATTING EXAMPLE 

|======================================|
GENERAL FIXED
|======================================|

Each department can have multiple headers, each of which is a different subsection that is scheduled to this department. There should be one space (one 'Enter' key) after each subsection

FORMATTING EXAMPLE 

|======================================|
GENERAL FIXED

FIXED IMPLANT 

PFM + FULL CAST 
|======================================|

Addendums

Under each header, each new line should be preceded by an indented addendum.

FORMATTING EXAMPLE 

***-*[insert preference text here]
   - [insert preference text here]

The asterisks ('*') represent the spaces that are used to create the addendum. 3 spaces ('Spacebar'), hyphen ('-'), 1 space ('Spacebar'), then your preference text.

Each addendum represents a single sentence for a preference. These lines can be formatted to display specifc defaults for a set criteria for a product, or a general preference.

FORMATTING EXAMPLE 

|======================================|
FULL DENTURE 
   - Denture type: Digital
   - Stippling: Yes
   - Festooning: Yes
   - Set-Up: Ideal
   - Teeth type: Economy
   - Avoid sharp edges on incisals
|======================================|

Each department has a standard template to utilize that showcases this format. You can find these templates at the end of this guide for each department. Defaults for doctors should be formated as [Criteria: selected preference]

You might find it necessary to add additional criteria, details, or conditional specifications regarding a preference. In this case, you can add a sub-addendum under the parent.

FORMATTING EXAMPLE 

|======================================|
FULL DENTURE 
   - Denture type: Digital
       - Dr will always send 2 scans, utilize the better one
   - Stippling: Yes
   - Festooning: Yes
   - Set-Up: Ideal
   - Teeth type: Economy
   - Avoid sharp edges on incisals
|======================================|

The formatting of this sub indented line is as follows:

FORMATTING EXAMPLE 

          ******-*[insert preference text here]
                - [insert preference text here]

Sometimes, there might be multiple doctors tied to a single account. Addendums are useful in clarifying what their own default preferences are for certain products.

FORMATTING EXAMPLE 

|======================================|
FULL DENTURE
- Denture type:
   - Dr Smith: digital
   - Dr Jones: Ivocap
      - Dr will want digital try-ins for setups.
|======================================|

Line Length

Preferences should ideally be made up of short, concise sentences/shorthand. The optimal line length is 50-60 characters per line, including spaces. Avoid long-winded writing, multiple sentences, or run-on sentences. A technician should be able to quickly look over a preference sheet and be able to pick up the key details for their department with ease.

Below is an example of a real preference that was attached to an account and how easily we can reduce its length and make it more readable.

Before

- IMPLANT preferences to always default to angled screw channel when the access hole is in an esthetic area or creates a thin area of porcelain. Also if the angled screw channel abutment is going to be too short for adequate retention when there is large restorative space (i.e. if the tooth is going to be very long.) then always go to custom abutment but screw-mentable

After

- Swap to ASC: ok to swap - If ASC abut is short for retnetion, ok to go to custom SR

These shortened preferences provide the same information, but with fewer words. Make note that some words are shortened, or unique symbols are utilized to save characters. Every little bit counts in helping a technician parse through a large chunk of information.

Dates

How to use Dates

When adding a new preference or changing an existing one, consider adding the date of when it was adjusted/made. This is useful for technicians to know if a preference is new or if has changed recently.

FORMATTING EXAMPLE 

                - Apply 10% discount on all removeables (10/26)
                - Dr does not want screws included in case (5/24)

Dates do not have to be added for all preferences. They should only be added if it is important in the context of the preference in question. ie. A suddent change in a doctor's preference, a temporary preference, or a time-specific preference.

Rule

Dates should be formatted with the month then year (MM/YY)

Do's and Dont's

Recommended practices

  • Use concise, unambiguous language
  • Keep related instructions together
  • Review existing instructions before making changes

Patterns to avoid

  • No all caps outside of headers
  • No exclamation marks ('!')
  • Do not repeat information in muktiple departments
  • Do not directly copy-paste something from a doctor's email
  • Do not make remarks about Doctor's mood, demeanor, or thoughts with ROE
  • Contradicting a previously written preference
